# FilePurger 产品需求文档 (PRD)

---

## 1. 产品概述 (Product Overview)

### 1.1 背景与痛点
对于使用 macOS 的用户而言，磁盘空间尤其是“下载 (Downloads)”和日常工作文件夹经常被大量时效性文件填满：
1. **下载目录堆积**: 安装包（`.dmg`, `.pkg`）、压缩包（`.zip`）、单次查阅的文档只用一次便长久闲置，占用大量宝贵的 APFS 磁盘空间。
2. **废纸篓缺乏自动维护**: macOS 自带的“30 天后清倒废纸篓”规则过于单一，既无法限制废纸篓占用的磁盘总容量，也缺乏对不同类型旧文件的精细生命周期管理。
3. **现有第三方工具痛点**: 许多工具界面臃肿、非原生体验、缺乏父子目录防重叠机制，或者在后台偷跑大量 CPU/内存资源，甚至一键粗暴全盘删除引发数据丢失恐惧。

### 1.2 产品定位与核心价值
**FilePurger** 是一款**专为 macOS 深度打造的轻量级纯菜单栏（Status Bar）旧文件自动清理助手**。
- **纯菜单栏常驻**: `LSUIElement = true`，Dock 栏不驻留图标，左键单击顶部菜单栏图标即可唤出主界面与控制菜单，开机静默常驻，内存占用低于 30MB。
- **多文件夹独立管理**: 左侧独立管理各监控文件夹，首次启动预置 `~/Downloads`，内置严格的父子目录重叠拦截与系统核心路径隔离防线。
- **系统废纸篓终极管家**: 顶部常驻废纸篓监控，支持“超龄天数清理”与“容量上限 (GB) 按 FIFO（移入时间）物理彻底清倒”双轮驱动。
- **瀑布式优先规则引擎**: 支持置顶永久保留白名单、组合路径通配符（大小写敏感）、`Date Added` 精确时间阈值，以及 4 种处置动作（列出 / 保留 / 直接移入废纸篓 / 严格逐一询问删除）。
- **内核级零压力监听**: 采用 macOS `FSEvents` 内核事件监听（配合 3 秒智能防抖）+ 小时级超龄心跳巡检，日常 CPU 占用保持为 0.0%。

## 2. 目标用户与使用场景 (User Scenarios)

### 2.1 典型用户画像
- **macOS 重度用户 / 开发者 / 设计师**: 经常从浏览器、邮件、Slack、微信下载大量临时文档与大体积安装包，需要系统在后台全自动维护文件夹整洁，又绝不容忍误删任何重要资产。
- **追求极简与秩序的 Mac 极客**: 喜欢类似 Bartender / Magnet 般纯净无感的菜单栏小工具，不希望 Dock 栏常驻杂乱图标，要求应用能一键彻底卸载 0 残留。

### 2.2 核心用例流程 (User Journey)
1. **场景 A：首次安装与静默守护**
   - 用户安装运行 FilePurger，应用自动在 macOS 顶部菜单栏出现小图标，默认开启“开机自启动”，Dock 栏不显示图标。
   - 打开主界面，左侧已默认添加 `~/Downloads` 文件夹。
2. **场景 B：为 Downloads 定制分级规则**
   - 用户在置顶规则中输入 `important_*, safe_work/**`，永久免死。
   - 新增规则 1：`*.dmg, *.pkg`，添加到文件夹超过 7 天，动作：**直接删除（移入废纸篓）**。
   - 新增规则 2：`*.zip, *.tar.gz`，添加到文件夹超过 14 天，动作：**询问后删除**。
   - 新增规则 3：`*`，添加到文件夹超过 30 天，动作：**列出**（仅在界面清单展示，便于审阅）。
3. **场景 C：询问后删除的严格人机确认**
   - 当规则 2 命中某个 15 天前下载的压缩包时，应用在界面中弹出专属确认窗口，向用户展示该文件的文件名、路径、大小与下载时间，用户手工点击【移至废纸篓】或【保留】。
4. **场景 D：废纸篓容量自动控顶**
   - 用户在废纸篓规则中设定：容量超过 10GB 自动按 FIFO 清理。
   - 当系统废纸篓因大文件堆积达到 12GB 时，应用自动将最早被移入废纸篓的文件逐个永久物理抹除，直至废纸篓体积平稳降至 10GB 以内。

## 3. 功能需求规格 (Functional Requirements)

### 3.1 运行形态与菜单栏交互 (FR-1: System Tray & Lifecycle)
- **FR-1.1 纯菜单栏常驻**: 专为 macOS 开发，配置 `LSUIElement = true`。平时在程序坞（Dock）完全不显示图标，启动后静默收起于顶部状态栏。
- **FR-1.2 左键菜单交互**: 单击左键直接弹出下拉菜单，包含：
  - 【打开主界面】（点击打开独立双栏控制台窗口，窗口关闭时仅隐藏而不退出进程）；
  - 【✓ 开机自启动】（可即时勾选/取消勾选，默认初始状态为开启 ON）；
  - 【彻底卸载本应用】（触发干净卸载流程）；
  - 【退出应用】（彻底终止进程）。
- **FR-1.3 开机自启动管理**: 采用 macOS 原生 `SMAppService.mainApp` API 注册与注销登录项，符合 macOS 13+ Ventura / Sonoma / Sequoia 安全规范。
- **FR-1.4 彻底卸载与 0 残留 (Clean Uninstall)**:
  - 用户在菜单或主界面点击“彻底卸载本应用”并二次确认后，应用自动：
    1. 注销 macOS 开机自启动项；
    2. 彻底抹除本地全部配置与缓存（`~/Library/Application Support/FilePurger` 等）；
    3. 将自身 `.app` 移入废纸篓并终止退出。

### 3.2 双栏主界面与文件夹管理 (FR-2: Folder Management)
- **FR-2.1 双栏布局**:
  - **左侧栏**: 文件夹管理列表；
  - **右侧栏**: 选中文件夹对应的规则配置区与下方的匹配结果清单。
- **FR-2.2 回收站项常驻**: 左侧列表最顶端常驻【回收站 (Trash)】，不可删除、不可移出、不可调整位置。
- **FR-2.3 初始预置**: 首次启动运行，左侧文件夹列表默认自动预置 `~/Downloads`（用户下载文件夹）。
- **FR-2.4 文件夹添加排他性防御**:
  - 用户可通过系统文件选取器（Tauri Dialog）或拖拽方式添加新文件夹；
  - **父子目录防重叠拦截**: 若用户尝试添加的文件夹是现有列表中任一文件夹的父文件夹或子文件夹（例如已有 `~/Downloads`，尝试添加 `~` 或 `~/Downloads/temp`），立即**弹出警告提示并坚决拒绝添加**；
  - **系统核心目录隔离**: 严禁添加 macOS 核心系统路径（如 `/`, `/System`, `/Library`, `/Applications`, `/usr`, `/bin` 等）。
- **FR-2.5 文件夹移除**:
  - 支持将文件夹从左侧列表中删除；
  - 该删除仅表示**“从自动清理监控列表中移除”**，磁盘物理文件夹不受任何影响，无二次确认弹窗打扰。

### 3.3 回收站专属自动规则 (FR-3: Trash Rules)
选中左侧顶部【回收站】时，右侧展示专属的两条内置规则（不可删除，不可添加其他规则）：
- **FR-3.1 规则 1：超龄天数自动清除**:
  - 设定超龄天数（天），自动永久物理删除整个系统废纸篓中存放超过该天数的文件；
  - 填 `0` 表示此规则不执行；初始默认值为 `0`。
- **FR-3.2 规则 2：容量超限 FIFO 自动清除**:
  - 设定回收站容量上限（GB）；
  - 当整个系统废纸篓总大小超过该设定值时，自动按 **FIFO（先进先出，以文件移入废纸篓的时间戳为准）** 逐个永久物理删除文件，直到总大小降至设定值以内；
  - 填 `0` 表示此规则不执行；初始默认值为 `0`。
- **FR-3.3 联动执行逻辑**:
  - 触发时，若两条规则均设置了有效数值，系统优先执行规则 1（超龄清理）；若清理完毕后废纸篓总体积仍高于规则 2 的容量阈值，继续执行 FIFO 淘汰。
  - 清理对象为整个 macOS 系统的废纸篓（`~/.Trash` 及挂载卷的 `.Trashes`）。

### 3.4 通配符与路径匹配规范 (FR-4: Pattern Specification)
- **FR-4.1 组合路径语法**:
  - 在同一表达式中组合表达文件夹层级与文件名；
  - `**` 表示递归所有子文件夹；
  - `*/` 或 `a*/` 表示单层文件夹（如一级直接子文件夹，或以 a 开头的一级子文件夹）；
  - 结尾为文件名通配符：
    - `*`: 表示所有文件；
    - `a*`: 表示以 a 开头的所有文件；
    - `*a`: 表示所有以 a 结尾的文件（不含扩展名，如 `banana.txt`）；
    - `a*.j*`: 表示以 a 开头且扩展名以 j 开头的文件。
- **FR-4.2 大小写严格敏感**: 所有路径通配符与文件名匹配严格区分大小写（`A*` 与 `a*` 为不同匹配）。
- **FR-4.3 逗号分隔多模式 (OR 逻辑)**:
  - 一条规则支持填入多个表达式，用中英文逗号（`,` 或 `，`）分隔；
  - 匹配逻辑为 **OR（或）**：只要命中其中任意一个模式即判定为符合该规则；
  - 自动过滤各项前后空格（trim）。

### 3.5 普通文件夹规则体系 (FR-5: Folder Rule Engine)
针对每个添加的普通文件夹，右侧提供分层规则流：
- **FR-5.1 置顶保留规则（白名单最高防线）**:
  - 每个文件夹常驻置顶一条专属保留规则，**不可调顺序、不可删除**；
  - 只要输入框中有内容即始终生效，首次默认为空；
  - 用户只需输入需要保留的文件/文件夹通配符（支持逗号隔开多项）；
  - **穿透免死保护**: 凡匹配此规则的文件，或匹配的子文件夹及其内部包含的所有各级子文件，全部**永久保留、绝不删除**，后续任何规则直接短路跳过。
- **FR-5.2 自定义普通规则管理**:
  - 支持新增、修改、删除规则；
  - 支持通过拖拽或按钮上下调整顺序，严格遵循**“从上到下优先匹配（First-Match 短路机制）”**，一旦匹配到第一个符合的规则后即刻执行并终止匹配；
  - 每条规则右侧带有独立的【启用/停用 Toggle 开关】。
- **FR-5.3 单条普通规则配置项**:
  - **Rule Name**: 规则名称（如 `清理安装包`）；
  - **Date Added**: 添加到该文件夹的时间阈值。单位支持 **分 (Minutes) / 小时 (Hours) / 天 (Days)**。基于 macOS 原生 `kMDItemDateAdded`。填 `0` 或选 `Any` 表示不限时间；
  - **File Name Pattern**: 文件名/路径通配符输入框（支持逗号分隔多项）；
  - **Execution Action（处置动作 4 选 1）**:
    1. **列出 (List Matches)**: 仅在下方清单中列出展示，不做任何删除或移动；
    2. **保留 (Keep)**: 命中后锁定保留，短路终止后续规则；
    3. **直接删除 (Directly Move to Trash)**: 直接移入 macOS 系统废纸篓；
    4. **询问后删除 (Ask before Trashing)**: 在应用内弹出专属确认卡片，对命中的每个文件/文件夹**严格逐一询问**，由用户单独决定【移至废纸篓】或【保留】。
- **FR-5.4 匹配结果清单区域**:
  - 右侧规则栏下方常驻【匹配结果清单】；
  - 展示当前文件夹中命中了“列出”规则的文件列表（展示文件名、所在路径、添加时间、大小）。

### 3.6 全局安全与排除底线 (FR-6: Global Security & Exclusions)
- **FR-6.1 隐藏文件自动免疫**:
  - 所有规则配置与扫描操作默认对以 `.` 开头的隐藏文件/隐藏文件夹（如 `.DS_Store`, `.localized`, `.git/`）无效，自动跳过；
  - **子文件夹连带清理豁免**: 当某个可见子文件夹整体触发删除时，允许连带将其内部包含的隐藏文件（如 `.DS_Store`）一并移入废纸篓。
- **FR-6.2 系统保留文件绝对豁免**:
  - 即使位于合法用户目录下，所有属于 macOS 系统保留的核心文件（如 `Desktop DB`, `.Spotlight-V100` 等）一律完全免疫、不予触碰。

### 3.7 零压力后台执行调度 (FR-7: Execution & Scheduling)
- **FR-7.1 内核级变动监听 (FSEvents)**:
  - 基于 macOS 原生 `FSEvents` 监听各监控文件夹的新建与变动；
  - 内置 3 秒智能防抖（Debounce）窗口，在写入完全停止后触发一次聚合规则匹配；
  - 无文件变动时监听线程休眠，CPU 占用率稳定在 0.0%。
- **FR-7.2 自然超龄小时级心跳**:
  - 每隔 1 小时执行一次极轻量扫描巡检（耗时 < 5ms），确保自然达到“超过 X 天”的文件能被及时捕获处理。
- **FR-7.3 随时手动立即执行**:
  - 主界面提供【立即扫描】按钮，用户可随时点按即刻执行全盘规则巡检。

## 4. 详细验收标准清单 (Acceptance Criteria)

- [ ] **AC-1 纯菜单栏与托盘交互**: 应用启动后在 Dock 栏无图标，顶部菜单栏显示图标；左键点击弹出包含【打开主界面】、【✓ 开机自启动】、【彻底卸载本应用】、【退出应用】的原生下拉菜单。
- [ ] **AC-2 开机自启动与彻底卸载**:
  - 点击“开机自启动”可正常在 macOS 系统设置登录项中注册/注销；
  - 点击“彻底卸载本应用”并确认后，登录项注销，`~/Library/Application Support` 全部配置清除，应用自身移入废纸篓并退出。
- [ ] **AC-3 文件夹父子重叠拦截**:
  - 列表中已有 `~/Downloads` 时，尝试添加 `~` 或 `~/Downloads/test`，系统弹出警告并坚决拒绝添加；
  - 尝试添加 `/System` 或 `/Library` 等系统目录同样被坚决拒绝。
- [ ] **AC-4 回收站超龄与 FIFO 清除**:
  - 设置回收站保留 15 天，容量上限 5GB；测试超龄文件被永久删除；当放入大文件超过 5GB 时，最早移入废纸篓的文件被优先彻底清除直到体积低于 5GB。
- [ ] **AC-5 通配符与大小写严格匹配**:
  - 规则 `a*.j*` 能够匹配 `apple.jpg`，但绝不匹配 `Apple.jpg`（大小写敏感）；
  - `*a` 能够匹配 `banana.txt`（主干以 a 结尾）。
- [ ] **AC-6 置顶保留白名单优先级**:
  - 在置顶规则输入 `keep*`，下方配置 `*` 超过 0 天直接删除；测试发现名为 `keep_123.txt` 的文件完好保留，其他文件进入废纸篓。
- [ ] **AC-7 四大处置动作精准性**:
  - “列出”动作的文件准确在下方清单表格呈现；
  - “直接删除”的文件瞬间移入系统废纸篓；
  - “询问后删除”的文件在应用内逐一弹出确认，只有用户点击确认才移入废纸篓。
- [ ] **AC-8 隐藏文件隔离与子文件夹连带清理**:
  - 扫描文件时自动跳过 `.DS_Store`；
  - 当整个子文件夹 `temp/` 被移入废纸篓时，其内部包含的 `.DS_Store` 随同移入。
- [ ] **AC-9 FSEvents 零压力监听**:
  - 在无变动时进程 CPU 占用为 0.0%，内存 < 30MB；向监控目录放入新文件后，3 秒防抖后自动触发匹配。
