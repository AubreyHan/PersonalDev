# 产品需求文档 (PRD) - GitHub 自动同步托盘应用

## 1. 文档元信息
* **项目名称**：GitHub 自动同步桌面应用 (GitHub Auto Sync)
* **项目代号**：`github-auto-sync`
* **版本状态**：v1.0.0 (MVP 规划)
* **创建时间**：2026-10-27

---

## 2. 背景与核心价值 (Background & Value)

### 2.1 痛点分析
现代开发者通常在多个设备（办公电脑、家用电脑、笔记本）间协作，或者在本地维护大量小项目、文档库（如 Obsidian 笔记库、脚本库）。开发者经常面临以下痛点：
1. **忘记 Push**：在一台电脑写完代码离开后，发现改动没有推送到 GitHub，另一台电脑无法继续工作。
2. **多仓库维护成本高**：拥有几十个仓库分布在不同的本地目录，逐个手动检查 `git status` 和 `git pull/push` 极其繁琐。
3. **传统 GUI 工具笨重**：传统的 SourceTree / GitHub Desktop 内存占用动辄数百兆，且不支持全自动后台监听与同步。
4. **Git 冲突处理门槛**：常规自动脚本在遇到冲突时直接崩溃报错，缺乏针对不同仓库的容错与优先级策略（如本地覆盖远端、远端覆盖本地）。

### 2.2 产品愿景
打造一款**轻量、常驻系统托盘、极低内存（< 40MB）、零登录配置**的跨平台 Git 自动同步助手。通过双栏设计，实现“指定父级文件夹即自动递归发现所有子仓库”，并通过右键菜单为每个仓库定制同步模式，彻底解放双手。

## 3. 用户角色与典型场景 (User Personas & Scenarios)

### 3.1 角色定义
* **多端协同开发者**：有多台开发机，希望工作目录的代码在编辑保存后无需手动敲命令就能即时上云。
* **数字花园 / 知识库作者**：使用 Markdown 笔记（Obsidian、Logseq），希望写完自动同步到 GitHub 私有仓库。
* **开源项目追踪者**：本地维护多个仓库，希望定期自动与远端对齐最新提交。

### 3.2 典型用例 (User Stories)
* **US-1 (托盘常驻)**：作为用户，我希望应用启动后自动隐身在系统托盘，不占用任务栏，右键能快速打开设置窗口或退出。
* **US-2 (多级文件夹自动搜索)**：作为用户，我希望添加 `~/Projects` 文件夹后，系统能自动把里面的所有 git 仓库扫描出来，无需我手动一个个导入。
* **US-3 (动态文件监听)**：作为用户，当我在已添加的文件夹里新建/克隆或删除了一个仓库，右侧列表能自动刷新，无需我手动点击“重新扫描”。
* **US-4 (策略化同步与防冲突)**：作为用户，对于笔记仓库我希望“本地优先”，对于临时拉取的依赖库我希望“远端优先”，对于协同项目我希望“双向同步（新覆盖旧）”。
* **US-5 (详尽 Commit 信息)**：作为用户，我希望自动提交的信息里不仅有时间，还能看到本次自动同步具体改动了哪些文件，方便追溯历史。

## 4. 功能规格需求 (Feature Requirements)

### FR-1: 系统托盘与主窗口生命周期
* **1.1 托盘驻留**：应用启动后默认进入系统托盘（macOS 菜单栏 / Windows 系统托盘），主窗口默认隐藏或启动时最小化至托盘。
* **1.2 极简右键菜单与优雅停机 (Graceful Shutdown)**：右键点击托盘图标仅弹出两个基础操作：
  * `打开主界面 (Open)`：唤起并置顶主界面窗口。
  * `退出应用 (Quit)`：**优雅关闭所有后台服务**——依次注销所有文件监听器（Watcher）、中止 5 秒防抖调度任务与 5 分钟定时轮询任务、等待正在执行的 Git 子进程安全结束（避免产生 `.git/index.lock` 残留）、持久化未写入的配置与状态，最后彻底退出程序，不留任何孤儿进程或残余线程。
  * *明确不做（Non-Goals）*：不在托盘右键放置“立即同步”、“暂停/恢复”等冗余业务操作。
* **1.3 窗口关闭行为**：点击窗口右上角关闭按钮（`X`）时，不退出程序，仅隐藏主窗口（Hide to Tray）。

### FR-2: 现代双栏式主界面布局
* **2.1 左栏（文件夹管理树）**：
  * **顶部固定项【全部文件夹】(All Folders)**：始终置顶，点击后在右侧展示所有已添加文件夹下汇总的 Repos。
  * **文件夹列表区域**：列出用户添加的本地根路径（显示文件夹名称与绝对路径 tooltip）。
  * **添加文件夹**：提供醒目的 `+ 添加文件夹` 按钮，点击调用原生系统目录选择对话框。
  * **文件夹防嵌套与防重校验 (Nesting Prevention)**：
    * **子目录拦截**：若新选目录是已有监控目录的子文件夹（例如已添加 `~/Projects`，再尝试添加 `~/Projects/app1`），系统自动弹窗拦截并提示：*“无法添加：该目录属于已添加文件夹【Projects】的子目录，已被纳入监控范围”*。
    * **父目录拦截**：若新选目录包含了已有监控目录（例如已添加 `~/Projects/app1`，再尝试添加 `~/Projects`），系统自动弹窗拦截并提示：*“无法添加：该目录包含了已监控的文件夹【app1】，为避免重复监听冲突，请先移除子文件夹后再添加”*。
    * **完全重复拦截**：若新选目录与已有目录完全一致，提示：*“该文件夹已存在于列表中”*。
  * **删除文件夹时的彻底清理 (Clean Removal)**：
    * 悬浮或右键列表项可触发“移除文件夹”。
    * **即刻停止所有服务**：后端立即终止针对该文件夹的所有 `notify` 监听实例，取消下属所有子仓库在途的 5 秒防抖计时器与定时轮询任务。
    * **清除所有关联记录与缓存**：从本地配置文件中彻底注销下属所有 Repo 的同步模式、最后同步时间等元数据，前端列表同步清空，杜绝内存与句柄残留（**注**：严禁删除用户本地硬盘上的实际代码工程文件）。
* **2.2 右栏（Git 仓库列表视图）**：
  * 展示选中文件夹（或全部文件夹）对应的 Git Repos 列表/卡片。
  * 列表支持空状态提示（如“未发现 Git 仓库，请添加包含 .git 的目录”）。

### FR-3: 仓库自动递归发现与动态监听 (Auto Discovery & Watcher)
* **3.1 递归扫描**：添加文件夹时，后台异步深度遍历搜索所有子目录，只要存在有效 `.git/` 目录即登记为一个可管理的 Git Repo。
* **3.2 动态感知**：
  * 监听文件系统目录变更。
  * 当用户在监控目录下执行 `git clone`、`git init` 或解压出新的 git 仓库时，界面自动追加该 Repo。
  * 当用户在终端中 `rm -rf` 删除了某个仓库，界面自动移除该 Repo。

### FR-4: Repo 项元信息与状态可视化展示
每个 Repo 卡片/行项目必须包含以下元素：
* **仓库基础信息**：仓库名称（目录名）、相对/绝对路径、当前所在分支名称（如 `main`、`dev`）。
* **同步策略徽标 (Badge)**：
  * 🟢 `双向同步`（绿色 Badge）
  * 🔵 `本地优先`（蓝色 Badge）
  * 🟣 `远端优先`（紫色 Badge）
  * ⚪ `停止同步`（灰色 Badge，新扫描到的默认状态）
* **同步运行状态**：
  * 同步中：转圈 Loading 动画。
  * 同步成功：绿色对勾或最后同步时间（如“10分钟前”、“刚刚”）。
  * 异常/报错：红色感叹号，悬浮显示错误详情（如网络超时、无远端分支等）。

### FR-5: 右键策略选择菜单 (4-Mode Context Menu)
在右侧任意 Repo 项上右键点击，弹出上下文菜单供用户切换同步策略：
1. **双向同步（如有冲突，新覆盖旧）**：
   * 自动 `pull` 和 `push`；如发生文件冲突，对比本地与远端最后修改时间/提交时间，最新者覆盖旧版本。
2. **本地优先（本地覆盖远端）**：
   * 本地改动作为权威版本。提交本地改动后，若远端存在分叉，执行覆盖推送（Force Push with lease），确保远端与本地一致。
3. **远端优先（远端覆盖本地）**：
   * 远端作为权威版本。丢弃或暂存本地未提交的修改，拉取远端最新分支并强制重置本地（`git reset --hard origin/<branch>`）。
4. **停止同步**：
   * 暂停该仓库的所有文件监听、自动提交与推送逻辑。
* **默认值规则**：首次发现并加入列表的所有新仓库，默认策略一律为 **【停止同步】**，避免未经用户确认直接向远端发起未预期的同步操作。
* **首次开启同步前置检查 (Initial Sync Pre-flight Health Check)**：
  * 当用户首次将某个 Repo 从【停止同步】切换至任一有效同步模式（双向/本地优先/远端优先）时，后台**立即触发前置同步健康检查**：
    1. **远程仓库关联校验**：检查该 Repo 是否已配置远程 URL（`git remote -v`）。若为纯本地 Repo（未配置 origin），拦截开启并弹出提示：*“无法开启同步：该仓库尚未关联远程仓库 (No Remote Origin)，请先配置远程地址”*。
    2. **工作区异常状态校验**：检查工作区是否处于 rebase、merge 冲突中断中（检查 `.git/MERGE_HEAD` 等标记）。若存在未解决的冲突，阻止开启并提示：*“工作区处于合并/冲突中断状态，请先手动处理”*。
    3. **远程网络与凭证连通性**：轻量级探测远程是否可达与有无权限。
  * **检查确认状态正确后**：切换为对应模式的彩色 Badge，并进入同步就绪状态（`idle`）；若检查失败，保持标红警告，阻止自动同步，保障代码安全。
* **策略切换即刻触发首次同步 (Auto-trigger Initial Sync on Mode Change)**：
  * 当仓库的同步策略状态发生变更（从【停止同步】切换至任意开启模式，或在双向同步/本地优先/远端优先之间切换）时，在模式切换生效后**立即自动触发该仓库的首次同步**；
  * 无需等待 5 秒本地变动防抖或 5 分钟远端轮询，为用户提供即时的策略生效与同步反馈。

* **无远端上游分支策略 (Unset Upstream Policy)**：
  * 若当前本地切换到了一个在 GitHub 远端尚不存在的新分支（无追踪上游），系统**不自动向远端推送创建新分支**；
  * 自动暂停该仓库的同步动作，界面标黄提示：*“当前分支尚未推送到远端，请手动 push 建立关联”*，保障远端分支体系不被随意污染。

### FR-6: 二合一触发机制 (Mode C)
* **6.1 本地实时防抖触发 (5s Debounce)**：
  * 仓库文件发生变动（监听忽略 `.git/` 本身内部的临时文件），进入 5 秒防抖窗口。
  * 5 秒内若无新文件变动，立即触发提交与推送管道。
* **6.2 远端定时轮询检查 (Periodic Poll)**：
  * 默认每隔 5 分钟（可在设置中微调）向远端执行 `git fetch` 检查是否有新的上游 Commit，触发对齐同步。

### FR-7: 携带变更内容的 Commit Message
自动生成的 Git Commit Message 必须体现结构化时间戳与本次同步的文件变更摘要，格式规范如下：
```text
auto-sync: 2026-10-27 14:05:00 - {N} files changed ({summary})
```
* 例如：
  * `auto-sync: 2026-10-27 14:05:00 - 3 files (modified: src/App.tsx, src/index.css; added: README.md)`
* 变更超出 3 个文件时自动截断显示：`3 files (modified: App.tsx, +2 more)`。

### FR-8: GitHub 大文件自动拦截与凭证规范
* **8.1 大文件 (>100MB) 自动写入 `.gitignore` 保护**：
  * 在执行 `git add` 收集变动时，系统遍历待提交文件大小。
  * 若发现单文件物理体积 $\ge 100\text{MB}$：
    1. 自动检查仓库根目录下是否存在 `.gitignore` 文件（若无则自动创建）。
    2. 检查 `.gitignore` 中是否包含 `# large files` 标签段落（若无则自动在文件末尾追加 `# large files`）。
    3. 将该大文件的相对路径自动追加至 `# large files` 标签下方，去重写入。
    4. 执行 `git rm --cached <path>` 将其从 Git 暂存区移出，避免推送至远端。
    5. 界面弹出友好提示：*“检测到大文件 [{filename}] (超过100MB)，已自动加入 .gitignore 的 # large files 标签下忽略，避免 GitHub 推送受阻”*。
* **8.2 凭证复用**：直接调用宿主系统的 `git` CLI。用户只需本地配置好 SSH Key（`~/.ssh/id_rsa` / `id_ed25519`）或系统钥匙串（macOS Keychain / Git Credential Manager），应用即可无缝推送，无需在界面输入账号密码或 PAT。
* **8.3 明确非目标 (Non-Goals)**：
  * 本阶段不内置复杂的代码三方对比/手动合并冲突编辑器（Conflict Resolving GUI）。
  * 不支持 SVN、Mercurial 等非 Git 版本控制系统。
  * 不存储用户的私钥或明文密码。

### FR-9: 偏好设置与开机自启动 (Settings & Auto-Start)
* **9.1 开机自启动开关**：
  * 在主界面左栏底部提供“⚙️ 设置”入口（或弹窗），支持用户勾选/切换 **【开机自动启动】**。
  * 默认状态：可由用户自由开启或关闭。
  * 底层能力：通过官方 `tauri-plugin-autostart` 注册系统原生启动项（macOS LaunchAgent / Windows Registry），开机登录后自动在托盘无感启动。
* **9.2 基础参数微调**：
  * 支持查看与微调本地防抖等待时长（默认 5 秒）与远端拉取轮询间隔（默认 5 分钟）。
* **9.3 应用彻底重置/卸载清理 (Factory Reset & Unregister)**：
  * 在设置中提供【彻底清理数据与注销自启】功能。
  * 执行时：自动退出所有后台服务（停止监听与定时调度）-> 注销操作系统开机自启注册信息（删除 macOS LaunchAgent plist / Windows Run 注册表键）-> 删除本地应用配置文件与缓存（`config.json` 等）-> 彻底退出应用，确保操作系统无任何死进程、残留文件或自启残留。

### FR-10: 初次使用与磁盘权限引导 (First-Run Disk Permission Guidance)
* **10.1 首次启动权限检测**：
  * 应用首次启动运行时（检测到未完成初次引导），主界面弹出亲和的“磁盘访问权限引导”弹窗。
  * 明确说明权限诉求：*“为了监听并自动同步您指定文件夹下的代码仓库，应用需要获得本地文件夹读取与写入权限。”*
* **10.2 原生权限申请与一键跳转引导 (macOS / Windows)**：
  * 触发一次安全的测试性读写检查（针对默认或受保护目录）。
  * 若系统（尤其在 macOS Catalina 及更高版本下的 TCC 机制）尚未授予文件夹/全盘访问权限，提供【授予磁盘访问权限】按钮，一键通过系统 URL Scheme（如 `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`）直达系统设置面板。
  * 用户完成授权后，提示“已获得授权”，标记 `firstRunCompleted: true`，永久关闭初次引导。

### FR-11: 运行日志与 FIFO 自动清理 (Logging & FIFO Rotation)
* **11.1 App 包体目录内聚存储（随应用删除一同彻底抹除）**：
  * 日志文件统一保存在 App 包体目录下（例如 macOS 应用内部路径：`GitHubSync.app/Contents/Logs/app.log`）；
  * 当用户在操作系统中将应用程序删除（如移入废纸篓）时，日志文件随 App 整体直接被彻底移除，无需单独卸载清理，杜绝产生外置离散垃圾文件残留。
* **11.2 FIFO 循环队列容量控制（严格保持在 1.0 MB 以下）**：
  * 单个日志文件上限严格控制在 **1.0 MB (1024KB)** 以内；
  * 当累积写入逼近 1MB 限制时，系统自动执行 **FIFO (First-In, First-Out) 队列修剪**：丢弃头部最早的历史日志行，保留最新约 700KB 记录，并保证对齐到完整行首，防止首行断裂；
  * 修剪后插入系统标识行：`[SYSTEM] --- 触发 FIFO 自动清理（保持容量在 1MB 以内），旧日志已淘汰 ---`，确保磁盘占用永不膨胀。
* **11.3 原生日志查看器界面 (LogViewer UI)**：
  * **入口**：在主界面左栏底部操作区提供「📜 运行日志」按钮；在系统托盘右键菜单中增加「查看运行日志」菜单项。
  * **容量指示徽标**：查看器顶部实时展示当前日志物理体积（例如：`容量: 12.4 KB / 1.0 MB (FIFO 循环)`）与存放绝对路径。
  * **分类筛选与即时搜索**：支持按级别标签（`ALL`, `SYNC`, `INFO`, `WARN`, `ERROR`）单选过滤；提供实时全文关键词过滤框。
  * **辅助操作**：
    * 自动滚动（Auto-scroll）开关（新日志到达时自动滚动到底部）；
    * 【拷贝全部】：一键复制当前筛选或全部日志到系统剪贴板；
    * 【访达定位】：在 macOS Finder 中高亮选定 `app.log`；
    * 【清空日志】：带二次确认弹窗，一键清空日志文件并重新初始化。

| **AC-1** | 托盘与启动/停机 | 启动 App，应用驻留托盘，无白屏闪退。右键托盘仅显示“打开主界面”和“退出”。关闭窗口时托盘依然常驻；右键点击“退出”时，系统优雅停止所有文件监听与后台轮询线程，安全结束在途 Git 命令并保存状态后，进程完全退出，无后台僵尸进程。 |
| **AC-2** | 文件夹添加与防嵌套拦截 | 点击 `+ 添加文件夹`，选择目录后左栏新增项。若选择已有目录的子目录、父目录或相同目录，系统精准弹出对应中文拦截提示，阻止添加，避免重复监听与竞争死锁。 |
| **AC-3** | 递归扫描与默认状态 | 选择一个嵌套多层 git 仓库的根目录，右栏正确列出所有子仓库；每个新仓库的 Badge 均为灰色 `[停止同步]`。 |
| **AC-4** | 动态增删 Repo | 在监控目录下新建一个文件夹并 `git init`，无需刷新界面，1~2 秒内右栏自动出现该仓库。在文件管理器中删除该目录，右栏自动消失。 |
| **AC-5** | 右键开启同步与前置预检 | 在右栏 Repo 右键选择【本地优先】时，系统自动触发前置检查（验证 remote origin 存在、无未解决的 rebase/merge 冲突）。校验通过后，Badge 变为蓝色 `[本地优先]` 并进入就绪；若仓库无远程源，则弹出拦截提示并标红告警。 |
| **AC-6** | 防抖自动同步与 Commit 信息 | 在开启自动同步的仓库中修改一个文件并保存，等待 5 秒防抖，系统自动完成 commit 并 push。使用 `git log -1` 查看最新提交信息，必须包含当前时间和被改动的文件名称。 |
| **AC-7** | 本地优先冲突处理 | 模拟远端存在不同提交，在“本地优先”模式下触发同步，远端被安全覆盖，本地代码不丢失。 |
| **AC-8** | 远端优先对齐 | 模拟本地有未推变动，在“远端优先”模式下触发同步，本地正确 reset 对齐远端最新状态。 |
| **AC-9** | 开机自启动配置 | 在设置界面开启“开机自启动”，系统登录项（如 macOS `~/Library/LaunchAgents`）中正确生成守护配置；关闭开关后自动清理。 |
| **AC-10** | 彻底删除与无残留注销 | 1. 移除单个文件夹时，后台对应 Watcher 与调度任务即刻停机，配置文件中抹除该文件夹及其所有 Repo 记录；<br>2. 点击彻底清理时，自启项被注销，配置目录完全清除，服务关闭并干净退出。 |
| **AC-11** | 初次启动磁盘权限引导 | 全新安装启动时，主界面显示权限授权说明弹窗；点击一键跳转按钮能正确打开系统“隐私与安全性”设置；授权后引导自动关闭，不再重复弹窗打扰。 |
| **AC-12** | 大文件 (>100MB) 自动忽略 | 在同步仓库中生成一个 105MB 的测试文件，触发同步。检查根目录 `.gitignore`，已自动出现 `# large files` 段落及该文件相对路径；`git status` 显示该大文件已被 ignore，其它小文件正常提交推送成功。 |
| **AC-13** | 日志查看与 FIFO 1MB 限制 | 1. 点击左栏日志按钮或托盘菜单打开日志查看器，能正常分页展示系统日志，支持等级过滤与搜索；<br>2. 模拟大批量连续写入超过 1MB 日志，日志文件容量严格截留在 1MB 以下，且最旧日志自动淘汰、最新操作完整保留；<br>3. 检查文件实际路径位于 `GitHubSync.app/Contents/Logs/app.log`，随 App 删除时一同彻底销毁。 |
