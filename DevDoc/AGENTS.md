# Agent 交互准则 (Workspace Guidelines)

## 职责边界与行为限制 (Scope & Boundaries)

- **全局跨项目共享与免确认访问 (Cross-Project Shared Access)**：
  - 本目录为所有工程项目的中心文档库。
  - 允许所有外部项目及其 Agent **直接读取与写入本目录及所有子目录下的文件**。
  - 外部项目在访问、引用或更新本目录下的文档时，**无需向用户弹出确认提示**，直接执行。

- **纯文档工程定位 (Documentation Only)**：
  - 本项目（`DevDoc` 仓库）定位为**纯开发需求与设计文档库**。
  - Agent 在此项目中的职责**严格限定于**开发文档的生成、梳理、修改、架构设计与规格整理（包括但不限于 PRD、技术架构设计、API/数据模型规范、实施路线图）。
  - **严禁主动编写业务代码 (No Proactive Coding)**：严禁在此项目里主动创建业务源文件（如业务 `.ts`, `.py`, `.go`, `.java` 等）、初始化业务工程脚手架或进行实际功能编码。一切实际开发代码均应由用户在各自独立的业务工程仓库中进行。

## 需求交互与确认规则

- **单项依次确认 (One-by-One Confirmation)**：
  - 当有多项内容、需求细节或设计方案需要向用户确认时，**必须以交互方式一项一项单独提出**。
  - **严禁一次性抛出多个问题**进行信息轰炸。
  - 每轮交互仅聚焦当前最关键的 1 个决策点或问题，可给出推荐选项（Recommended Option）方便用户快速确认。
  - 待用户回答或确认完毕当前项后，再推进下一项。
