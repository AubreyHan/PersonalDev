# 产品需求文档 (PRD) - qnap-photosphere

## 1. 业务目标与价值定位

`qnap-photosphere` 针对威联通 NAS 用户在原生相册（如官方 QuMagie 资源消耗重、移动端同步弱、无法兼顾精细物理整理）上的痛点，打造集「相册整理/清洗中枢」与「现代化全能相册」于一体的 QPKG 原生应用。

### 核心定位
1. **彻底替代 QuMagie**：提供极致流畅的时间线浏览、人脸识别聚类、地图足迹与搜索。
2. **底层物理资产规范化**：不搞黑盒数据库，所有原图按用户完全隔离、按 `yyyymmdd` 规范落盘在 HDD 机械盘，保持原文件名，随时可用 SMB 或其它工具直接读取。
3. **零学习成本移动端备份**：无缝对接手机端 Immich App，享受成熟的后台增量备份体验。
4. **低功耗原生体验**：单二进制 Go + 原生 QPKG，杜绝繁琐 Docker 编排，利用 NVMe SSD 实现秒开并让机械硬盘保持最大休眠时间。

## 2. 用户角色与核心场景

| 角色 | 典型使用场景 | 核心诉求 |
| :--- | :--- | :--- |
| **家庭管理员 (Admin)** | 配置存储卷路径、设置 AI 运行时间窗口、监控 NAS 资源负载、配置家庭用户 | 原生安装无侵入、系统轻量稳定、不会搞崩 NAS 或狂占 CPU |

## 3. 功能需求规格 (Features & Specs)

### 3.1 资产监控、导入与物理归档
- **FR-1.1 自动监控导入目录**：
  - 监控各用户专有的 `Inbox` 目录（或手机 App 自动同步入口）。
  - 支持格式：JPEG, PNG, HEIC/HEIF, RAW（CR2, CR3, ARW, NEF, DNG）, WebP, MP4, MOV。
- **FR-1.2 自动归档落盘规则**：
  - 读取 EXIF 拍摄时间，自动将照片移动到该用户的 HDD 正式库路径：`/share/Photos/users/{username}/yyyymmdd/`。
  - **保持原文件名不变**。
- **FR-1.3 同名文件防覆盖策略**：
  - 若目标目录已存在同名文件：
    - 比对两者 SHA-256：若内容完全相同，判定为重复，移入 `.trash/duplicates/` 待清理；
    - 若内容不同（相机重置或多机位同名），自动采用序号后缀重命名保留（例如 `IMG_0001_1.JPG`）。
- **FR-1.4 资产组联动 (Asset Group)**：
  - 自动识别配对文件（如苹果 Live Photo：`IMG_0001.HEIC` + `IMG_0001.MOV`；单反成对：`IMG_0001.CR3` + `IMG_0001.JPG` + `IMG_0001.XMP`）。
  - 移动归档、重命名、移入回收站时默认保持原子联动。

### 3.2 缺失 / 错误 EXIF 修复队列
- **FR-2.1 无 EXIF 拦截进入复核区**：
  - 对于没有拍摄时间（如微信另存图、部分截图、老扫描照片）的文件，系统不直接粗暴落入当天日期，而是拦截进入「待修复/待确认区」。
  - 系统尝试通过正则从文件名解析可能的时间戳（如 `mmexport_1730000000.jpg`, `Screenshot_20261030_...`）并作为推荐时间。
- **FR-2.2 Web 端批量修复与写回**：
  - 用户在 Web 端可批量确认或手动调整拍摄时间、时区和地理位置。
  - 确认后，底层调用内嵌工具标准写回文件 EXIF 元数据，随后自动迁移至对应的 `yyyymmdd` 归档目录。

### 3.3 重复与相似照片清理
- **FR-3.1 精确去重 (SHA256)**：
  - 导入期拦截与正式库定期巡检，字节一致的重复照片一律识别并隔离到回收站。
- **FR-3.2 视觉相似 / 连拍聚类 (pHash)**：
  - 基于感知哈希 (pHash) 算法计算汉明距离，在时间窗口（如同一天内）将相似连拍或不同分辨率版本归为一组。
- **FR-3.3 并排对比人工决策**：
  - Web 端提供左右/网格并排参数对比（分辨率、大小、拍摄参数、直方图）。
  - 不做自动预判删除，由用户直接手动点击勾选保留项与淘汰项。

### 3.4 快速挑片工作流
- **FR-4.1 键盘流快捷操作**：
  - `←` / `→`：无缝前后切换。
  - `P` (Pick)：标记保留（优选）。
  - `X` (Reject)：标记淘汰。
  - `1-5`：评定星级；`0`：清除星级。
- **FR-4.2 淘汰批处理**：
  - 一键将所有标记为 `Reject` 的照片批量移入回收站，或支持单独“保留 JPG 删除 RAW”的精细操作。

### 3.5 现代全能相册浏览体验
- **FR-5.1 响应式秒开时间线**：
  - 基于 SSD 预生成的双层 WebP 缩略图（小图 300px 快速网格，大图 1920px 沉浸灯箱）。
  - 虚拟滚动加载，几万张照片流畅滑动不白屏。
- **FR-5.2 虚拟相册与家庭共享**：
  - 物理路径与 UI 解耦。用户可以创建自定义相册，原图位置不受影响。
  - 支持将相册设为「家庭公共相册」，全家可见。
- **FR-5.3 人脸与语义 AI（低负载调度）**：
  - 人脸检测、对齐与聚类展示；人物重命名合并。
  - 基于 CLIP 模型的本地文本搜图（如“海边”、“小狗”、“雪景”）。
  - 严格遵循后台限流规则，仅在夜间或空闲时段运行，CPU 负载 >75% 动态让出。

### 3.6 移动端 Immich 兼容协议
- **FR-6.1 Immich API 子集模拟**：
  - 模拟 `/api/server-info`, `/api/auth/login`, `/api/asset/upload`, `/api/sync` 等核心接口。
  - 手机安装原生 Immich App，填写 NAS IP:端口 与分配的账号，开启无感后台上传。

## 4. 验收标准清单 (Acceptance Checklist)

- [ ] **QPKG 原生性**：通过 QDK 构建出 `.qpkg`，能够在 TS-873A (QTS 5.x) App Center 顺利安装并启动，桌面出现图标。
- [ ] **冷热分层存储**：验证 SQLite、WebP 缩略图是否完全保存在指定 SSD 卷；物理原图是否保存在 HDD 机械卷。
- [ ] **物理归档防同名**：测试导入同名但不同内容的照片，系统应自动在目标 `yyyymmdd` 中加后缀生成 `_1`，绝不发生文件覆盖丢失。
- [ ] **EXIF 修复写回**：测试无 EXIF 照片在 Web 端修改日期后，原图 EXIF 头信息被真实改写并重归档至对应日期目录。
- [ ] **挑片快捷键**：在时间线全屏灯箱中，按 `P` / `X` / `1-5` 能毫秒级完成状态切换，一键移入回收站正常工作。
- [ ] **AI 动态温控**：测试模拟系统负载拉高到 80% 时，后台 ONNX 人脸分析任务自动挂起让出算力。
