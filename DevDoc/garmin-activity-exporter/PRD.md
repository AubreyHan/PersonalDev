# 产品需求文档 (PRD) - Garmin Activity Exporter

## 1. 背景与目标 (Background & Goals)

### 1.1 背景
佳明 (Garmin) 是全球顶尖的运动穿戴设备品牌。尽管 Garmin Connect 网页端与移动端 App 提供了详尽的运动数据展示，但在数据导出与本地离线归档方面存在明显的痛点：
1. **官方网页导出繁琐**：每次导出单条运动的 GPX/TCX 轨迹必须逐个点进活动详情页手动点击导出，缺乏对历史运动的批量检索与多选导出能力。
2. **多平台迁移壁垒**：许多用户因更换设备（如转投 Suunto/COROS 或 Apple Watch）、向 Strava/郁金香等第三方社区平台同步数据、或自行基于 GIS/Python 进行训练量化分析，急需将历史轨迹文件完整导出到本地。
3. **中国区与国际区壁垒**：Garmin.cn（佳速度/中国区）与 Garmin.com（国际区）账号体系与认证端点相互隔离，现存大多数开源命令行脚本（大多基于国外的 python-garminconnect）对中国区 SSO 认证兼容不稳定，且无图形界面，门槛极高。

### 1.2 核心目标
打造一款现代、轻量、高颜值的跨平台桌面客户端，解决 Garmin 用户的以下核心诉求：
- 提供图形化界面，实现对历史运动列表的可视化浏览与快速检索。
- 原生支持 Garmin 中国区与国际区双账号登录，无痛认证。
- 支持按时间、类型灵活勾选批量导出通用 GPX / TCX 格式轨迹。
- 支持一键增量导出，自动同步未备份活动。
- 支持用户自定义选择下载目录，所有文件直接平铺导出至该目录，无需建立任何年/月子目录。

## 2. 用户角色画像 (User Personas)

1. **多平台运动达人 (Alex)**：
   - 跑步、骑行、铁人三项爱好者，日常佩戴 Garmin Forerunner/Edge 码表。
   - 需要定期将 Garmin 中的 GPX 轨迹导出并手动上传至海外 Strava 或自建的跑步数据分析博客。
2. **佳明国内区普通跑者 (李明)**：
   - 使用国行 Garmin 腕表，账号注册在 Garmin.cn。
   - 不懂 Python 或终端命令行，希望有一个带 GUI 界面、开箱即用的桌面软件，直接勾选本月的半马、十公里跑步记录导出为 GPX 文件。
3. **数字仓鼠与数据备份极客 (Sarah)**：
   - 拥有 5 年以上的 Garmin 运动历史，担心云端数据丢失或被平台锁定。
   - 追求一键“全量增量备份”，希望将所有轨迹以规范防重命名直接平铺备份到指定的本地文件夹或移动硬盘，无需层级子目录嵌套。

## 3. 功能需求规格 (Functional Requirements)

### 3.1 账号体系与双区认证 (Authentication & Regions)
- **FR-1.1 双区切换**：
  - 登录界面显式提供单选切换：`Garmin Global (国际区)` 与 `Garmin China (中国区 - garmin.cn)`。
  - 切换区域后自动调整底层 SSO 登录端点与服务主机域名。
- **FR-1.2 登录凭据与会话管理**：
  - 支持账号密码输入登录。
  - 支持 Remember Me（记住登录态）：底层保存获取到的 OAuth Access/Refresh Token 及 Cookie Jar。
  - 敏感凭据（如选择保存密码）必须调用系统原生安全存储（macOS Keychain / Windows Credential Manager / Linux Secret Service），严禁明文存储到普通文件。
- **FR-1.3 MFA / 二步验证支持**：
  - 若用户账号开启了邮件/短信二次验证码（MFA），应用需弹出二次验证输入对话框，并将验证码回填提交以完成认证。
- **FR-1.4 登录态守护与自动续签**：
  - 启动应用时自动读取本地缓存的 Token 尝试静默登录。
  - 若 Token 过期，自动尝试 Refresh Token 刷新；若完全失效，优雅引导用户重新登录，不破坏已存在的本地导出历史。

### 3.2 活动列表浏览与多维检索 (Activity Explorer)
- **FR-2.1 极简列表呈现 (Minimalist List View)**：
  - 界面采用清爽的列表/表格视图展示活动，**严格精简显示字段，仅包含以下 3 个核心列**：
    1. **名字 (Activity Name)**：活动标题（如“奥森 10km 晨跑”）。
    2. **日期 (Date)**：运动开始日期（格式为 `YYYY-MM-DD`，可选包含具体时分）。
    3. **类型 (Activity Type)**：运动分类标签或专属图标（如 跑步、骑行、游泳）。
  - 每行左侧提供多选勾选框（用于多选批量导出或多项合并），右侧附带状态标签（未导出 / 已导出）。无需展示复杂的配速、心率、爬升等冗余指标，保持界面极致极简。
- **FR-2.2 多维筛选与搜索**：
  - **起止日期精确范围筛选 (核心)**：
    - 界面提供直观的**双日历控件 (Calendar Picker)**，支持用户分别选择「起始日期」与「截止日期」。
    - 筛选范围为闭区间 `[起始日期 00:00:00, 截止日期 23:59:59]`，严格包含起始日期与截止日期当天的所有运动活动。
    - 日历控件支持快捷点击（今天、昨天、本周、本月）或在日历网格中直接点选起止日期。
  - **运动类型下拉选择 (Dropdown Select)**：
    - 采用规范的**下拉选择框 (Dropdown / Select 控件)** 供用户切换运动类型。
    - 选项包括：全部类型 (All)、跑步 (Running)、骑行 (Cycling)、徒步/步行 (Walking & Hiking)、游泳 (Swimming)、室内健身 (Fitness Equipment) 等，选择后列表即时按选定类型过滤。
  - **关键字过滤**：支持根据活动标题（如“TNF100”、“晨跑”、“奥森 L判”）即时过滤列表。
- **FR-2.3 列表分页与全量拉取**：
  - Garmin API 为分页接口（每页典型 20~100 条）。
  - 支持虚拟滚动或瀑布流分页拉取，并提供“加载全部历史活动”按钮，拉取时显示进度条与统计（如“已加载 320 / 1280 条”）。

### 3.3 轨迹导出引擎 (Export Engine)
- **FR-3.1 核心支持格式**：
  - **GPX (`.gpx`)**：GPS Exchange 格式，包含经纬度、时间戳、海拔及扩展心率/踏频点，通用性最强。
  - **TCX (`.tcx`)**：Training Center XML 格式，包含分段（Laps）详细数据，深度支持训练区间分析。
  - 导出时允许用户在界面配置中选择默认导出格式（默认首选 GPX，可选 TCX，或两者同时导出）。
- **FR-3.2 批量勾选导出**：
  - 表格行勾选框：支持单选、按 Shift 连续多选、一键勾选当前页或一键勾选所有筛选出的活动。
  - 顶部操作栏显示“导出选中项 (N 条)”，点击触发批量下载任务。
- **FR-3.3 一键增量同步 (Incremental Sync)**：
  - 提供醒目的“一键同步最新”操作。
  - 系统对比本地导出索引库，自动找出云端存在但本地尚未导出的所有活动，自动加入下载队列，无需用户手动寻找差异。
- **FR-3.4 限流与并发控制**：
  - 为避免触发 Garmin 官方反爬虫及 429 Too Many Requests 封禁，导出引擎内置队列并发控制器（默认限制并发数为 2，任务间附带 300ms~800ms 随机微小抖动延时）。
  - 支持暂停、继续、取消下载队列。
  - 下载失败提供自动重试机制（最大重试 3 次，采用退避算法）。
- **FR-3.5 多活动轨迹合并导出 (Multi-Activity Merge Export - 核心数据保真)**：
  - **触发交互**：当用户在表格中勾选 >= 2 条活动时，批量操作栏激活「合并导出为一个文件」按钮。
  - **数据完整性保真 (Data Integrity)**：
    - **严格时序对齐**：自动提取各分段运动的真实开始时间戳，按严格的时间升序重新对齐轨迹点流。
    - **传感器与扩展指标零丢失**：对每个轨迹点 (`<trkpt>` 或 `<Trackpoint>`)，无损保留其高程 (`<ele>`)、UTC 时间戳 (`<time>`) 以及 Garmin 特有扩展数据（心率 `<hr>`、踏频 `<cad>`、温度 `<temp>`、功率 `<power>` 等 TrackPointExtension 节点）。
    - **GPX 结构合规**：采用多分段 `<trkseg>` 标准 XML 容器组织各段活动，确保导入 Strava、Apple Watch、两步路等第三方平台时能够被完整无缝解析并准确统计总里程与总用时。
    - **TCX 结构合规**：完整保留所有活动的各圈 `<Lap>` 数据，合并后自动重算活动总用时 (`TotalTimeSeconds`)、总距离 (`DistanceMeters`)、最高心率与平均心率。
  - **合并文件命名**：默认命名形如 `{startDate}_{type}_合并_{N}段活动_{firstId}.gpx`。

### 3.4 存储管理与平铺直存 (Storage & Flat Directory)
- **FR-4.1 自定义保存目录**：
  - 用户可通过系统原生目录选择器设定导出目标路径（如 `~/Downloads/Garmin_Activities`）。
- **FR-4.2 平铺直存 (无需建立子目录)**：
  - 所有导出的活动文件（`.gpx` 或 `.tcx`）一律**直接平铺写入用户指定的该下载目录中**。
  - **无需且严禁自动创建年份、月份或其它嵌套子目录**，保持文件结构平铺直观。
- **FR-4.3 命名规则与重名防冲突**：
  - 默认采用规范且具备唯一性的命名规则：`{date}_{type}_{name}_{id}.gpx`（例如 `2026-11-03_跑步_奥森夜跑_16892401234.gpx`），防止同日多项运动或同名运动在平铺目录下发生文件名覆盖冲突。
- **FR-4.4 本地定位与快捷交互**：
  - 对已导出的活动，在列表中提供“在文件夹中显示 (Reveal in Finder/Explorer)”快捷操作。

## 4. 非功能性需求 (Non-Functional Requirements)

- **性能与体积**：
  - 基于 Tauri 2.0 构建，二进制安装包体积在 15MB~25MB 以内。
  - 启动时间 < 1.0s，闲置内存占用不超过 60MB。
  - 即使加载 2,000+ 条活动记录，基于前端虚拟化表格仍能保持 60 FPS 流畅滚动。
- **安全性与隐私**：
  - 100% 本地运行，所有账号凭据、Cookie、活动数据直接在本地设备与 Garmin 官方服务器之间交互，绝无任何第三方中转服务器收集隐私。
  - 凭据均经由 OS 安全钥匙串存储，防止本地纯文本泄露。
- **健壮性与反爬兼顾**：
  - 模拟真实浏览器请求头（User-Agent、Referer、Sec-Fetch-*），正确处理 Cloudflare / Akamai 验证响应。
  - 网络波动时具备指数退避重试能力。

---

## 5. Non-Goals (本阶段明确不做的范围)

- **不做自建云同步后端**：不架设公共同步服务器或收取订阅费用，纯本地独立工具。
- **不做复杂的社交网络同步**：首期聚焦将 GPX/TCX 文件导出到本地，不直接对接 Strava OAuth API 自动双向上传（用户可手动将生成的 GPX 批量拖入 Strava 网页）。
- **不做原厂 FIT 文件的底层字节码级修补**：本应用直接通过 Garmin 官方 export 接口下载 GPX/TCX，不对轨迹数据进行平滑或篡改。

## 6. 验收标准清单 (Acceptance Criteria)

- [ ] **双区登录验证**：
  - 给定国际区账号，在选择 Global 时能正常登录并列出活动；
  - 给定中国区账号，在选择 China 时能成功完成 SSO 握手并拉取 `connect.garmin.cn` 数据；
  - 开启 MFA 时能正常弹窗让用户输入 6 位验证码并完成登录。
- [ ] **离线凭据持久化**：
  - 勾选记住登录后，重启应用能直接进入主界面并自动展示活动，无需重复输入密码。
- [ ] **列表与筛选**：
  - 成功分页拉取最近的活动，以极简列表方式清晰渲染「名字」、「日期」与「类型」3 个核心字段；
  - 能够通过日历控件精确选择起止日期区间（闭区间包含当天）以及通过下拉菜单筛选运动类型。
- [ ] **GPX/TCX 导出与文件生成**：
  - 勾选单条或多条记录，点击导出后，在指定目录生成标准的 `.gpx` 或 `.tcx` 文件；
  - 生成的文件能够正常导入 Apple Watch、Strava、两步路等第三方软件，轨迹图与海拔图完整无断点。
- [ ] **增量导出**：
  - 已导出的记录被正确标记并在本地持久化，点击“增量导出”时仅下载新产生的未导出记录。
- [ ] **多活动轨迹合并无损验证**：
  - 勾选 2 条或以上具有时间前后顺序的活动，点击“合并为一个文件导出”；
  - 生成的合并 GPX/TCX 文件中，所有原始轨迹点、心率、踏频、海拔数据全部完整保留，时序单调递增，成功通过 Strava 校验解析为总里程/总耗时无误的单次运动。
- [ ] **平铺直存与路径规约**：
  - 生成的文件名符合命名规则且包含 ID 防冲突，全部直接保存在用户指定的文件夹内，未产生任何年/月子目录。
