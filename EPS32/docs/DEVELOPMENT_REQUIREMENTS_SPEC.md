## 一、 项目背景与硬件平台规格

本项目基于微雪 **Waveshare ESP32-S3-Touch-AMOLED-1.75** 评估开发板，构建一款具备高刷新率、多页面滑屏交互、多星座 GNSS 追踪和高精度气压/海拔动态监测的嵌入式智能终端。

### 1.1 核心硬件架构参数

| 模块类别 | 硬件型号 / 规格 | 通信接口 / 映射引脚 | 技术特性与配置要求 |
| :--- | :--- | :--- | :--- |
| **主控芯片** | **ESP32-S3** (Revision v0.2) | 片上集成 (Dual-core Xtensa LX7 @ 240MHz) | 开启 64KB Data Cache、1000Hz FreeRTOS Tick |
| **片外存储** | **16MB Flash** + **8MB PSRAM** | Octal SPI (OPI @ 80MHz) | Flash 选用 QIO 80MHz，PSRAM 选用 Octal 80MHz |
| **AMOLED 屏幕** | **CO5300** 控制器 (466×466 圆形视网膜屏) | QSPI (Quad SPI) 接口 | 采用片内 SRAM 双缓冲（禁止走 PSRAM 弹跳缓冲） |
| **触摸面板** | **CST9217** 高精度电容触控 | I2C 接口 (`SDA: IO4`, `SCL: IO5`) | 支持多点触控与左右滑动手势 |
| **GNSS 模块** | **Quectel LC76G** (移远多星座定位) | I2C 接口 (`SDA: IO4`, `SCL: IO5`) | 支持 GPS+BDS+GLONASS+Galileo，标准 1Hz 吐出 |
| **IO 扩展** | **TCA9554PWR** (I2C IO 扩展器) | I2C 接口 (`0x20`) | `EXIO7` 控制 LC76G 硬件复位引脚（默认拉高） |
| **存储卡槽** | MicroSD / TF 卡槽 | SDMMC 1-line / 4-line 模式 | 支持挂载至 VFS `/sdcard` 用于轨迹离线持久化 |
| **调试下载** | 原生 USB Serial/JTAG (`VID:0x303A, PID:0x1001`) | USB Type-C 物理口 (`/dev/cu.usbmodem101`) | 采用非阻塞日志打印规避上位机断连阻塞 |

## 二、 快速环境搭建与跨电脑开发指南

为确保在任何其他电脑（macOS / Linux / Windows WSL）上均可即刻构建并烧录，遵循以下标准化环境搭建流程：

### 2.1 基础依赖与环境安装
- **ESP-IDF 版本要求**：**`ESP-IDF v5.5.6`**（或 `>= 5.3`）
- **工具链**：`xtensa-esp-elf-gcc 14.2.0`、`CMake >= 3.20`、`Ninja`、`Python 3.9+`
- **组件包管理**：`idf-component-manager`（自动从 Espressif 官方组件库拉取 `waveshare/esp32_s3_touch_amoled_1_75` 和 `lvgl/lvgl`）

### 2.2 本地一键环境激活脚本 (`env.sh`)
项目根目录下已配置好本地自包含环境脚本：
```bash
# 激活本地编译链与环境变量
source ./env.sh

# 标准编译工程
idf.py build

# 烧录并监听串口输出（自动指向 /dev/cu.usbmodem101）
idf.py flash monitor
```

### 2.3 关键 SDK 配置 (`sdkconfig.defaults`)
跨电脑迁移时务必保留以下关键配置参数：
- `CONFIG_IDF_TARGET="esp32s3"`
- `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y`
- `CONFIG_ESPTOOLPY_FLASHMODE_QIO=y` / `CONFIG_ESPTOOLPY_FLASHFREQ_80M=y` / `CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y`
- `CONFIG_SPIRAM=y` / `CONFIG_SPIRAM_MODE_OCT=y` / `CONFIG_SPIRAM_SPEED_80M=y`
- `CONFIG_FREERTOS_HZ=1000`
- `CONFIG_LV_COLOR_16_SWAP=y` / `CONFIG_LV_MEM_CUSTOM=y`

| |       +------------------------------------+       | |
| |       |              ALTITUDE              |       | |

| |       +------------------------------------+       | |

### 3.1 双侧环形信号强度弧线（顶层常驻）
- **左侧弧线（GPS 信号）**：
  - 从屏幕圆周底部向上沿圆弧延伸，采用亮绿色（`#00E676`）抗锯齿描边；
  - 根据搜星状态映射强度（`0% ~ 100%`）；
  - **未定位状态（`fix=0`）**：弧线高度抑制在低位并呈优雅呼吸慢闪，提示正在捕获星历；
  - **定位锁定状态（`fix=1`）**：根据有效卫星平均信噪比及颗数映射至对应刻度常亮。
- **右侧弧线（Wi-Fi 信号）**：
  - 从屏幕圆周底部向上沿右侧圆弧对称延伸，亮绿色显示；
  - 根据当前 AP 的 RSSI 强度动态映射（`-90 dBm` 映射为 `8%`，`-50 dBm` 映射为 `100%`）；未连接 AP 时自动归零隐藏。

### 3.2 顶层时间与自动时区显示
- **显示位置**：物理屏幕正顶端居中。
- **显示格式**：标准 **24 小时制**（`HH:MM`），字号适中清晰，与圆周顶部保持适当内边距。
- **时区确认机制**：**无需联网 NTP，由 GNSS 经度坐标全自动解算**：
  - 通过接收到的卫星定位经度进行时区划分：
    $$\text{Timezone Offset} = \operatorname{round}\left(\frac{\text{Longitude}}{15.0}\right) \times 60 \text{ 分钟}$$
  - 在中国区域（东经 $105^\circ \sim 127.5^\circ$），自动解算为 **UTC+8（北京时间）**，实现开机定位即获得精准本地时间。

### 3.3 圆形屏幕安全区（Safe-Area Inset）
- 屏幕物理外径为 $466\text{ px}$；
- 边缘双侧弧线、时钟及外壳遮光区向内缩进 $37\text{ px}$；
- **全页面通用安全区容器**：直径设定为 **$392\text{ px}$**（$466 - 2 \times 37$）；
- **布局规范**：所有后续开发的功能页面元素必须严格约束在该安全容器内，严禁与左右两侧的信号圆弧发生视觉重叠。

### 3.4 手势滑动多页面架构（Gesture Multi-Page）
- **交互逻辑**：全屏支持手指水平左右滑动手势切换页面，支持拖拽跟随与松手弹性对齐；
- **无显式 TabBar**：页面上禁止常驻传统 TabBar 或页面菜单，保证沉浸式全屏视图；
- **瞬态分页指示点（Transient Page Dots）**：
  - 屏幕正底端设有一排微型分页圆点；
  - 仅在手指触控滑动时或页面发生切换时淡入显示；
  - 停止滑动 2 秒后自动通过平滑动画淡出至完全透明。

## 四、 页面功能详细规格

### 4.1 第一页（Page 1）：海拔高度计与趋势分析（已落地完整实现）

该页面分为标准的 **上、中、下三栏式黄金分割布局**：

#### 1. 上栏：实时海拔高度显示
- **标题**：弱化色彩小号文本 `ALTITUDE`；
- **数值字体**：专用定制 112px 矢量点阵大字体（[`ui_font_digits_112`](file:///Users/aubreyhan/Tools/git_repo/PersonalDev/EPS32/main/ui_font_digits_112.c)），带单位 `m`；
- **防抖与滤波**：引入指数加权移动平均（EMA 滤波），消除 GNSS 垂直定位带来的高频毛刺抖动；
- **未定位保护**：在 GNSS 尚未取得首个有效 3D Fix 之前，严禁显示假高度，显示优雅的 `Searching...` 状态占位符。

#### 2. 中栏：1 小时 FIFO 高度变化趋势折线图
- **时间窗口**：严格定义为 **最近 1 小时（3600 秒）FIFO 环形滑动窗口**；
- **先进先出（FIFO）机制**：
  - 队列最大容量为 3600 节点；
  - 每次 1Hz 收到有效高度采样时，队首自动弹出时间戳早于 `Current_Time - 3600s` 的旧数据；
  - 队尾压入新采样点，折线图整体在时间轴上从右向左匀速平移；
- **折线卡片外观**：
  - 暗绿色卡片底板，内置 3 条水平参考网格虚线；
  - 左上方指示标签：`TREND 1H`；
  - 右上方动态量程文本：实时显示当前 1 小时窗口内的极小与极大值（如 `12 ~ 18 m`）；
  - 折线样式：亮绿色抗锯齿 Polyline，折线最右端带白色高亮圆点指示当前实时点；
  - 动态纵轴比例：保底最小纵向跨度 10 米，避免静止漂移时折线剧烈失真跳变。

#### 3. 下栏：本次加电会话极值统计
- **分栏布局**：左右对称两区，中轴采用纵向细微暗线分割；
- **左侧（`MIN ALT`）**：统计并实时刷新自本次加电开机以来的 **最低海拔**（`XX m`）；
- **右侧（`MAX ALT`）**：统计并实时刷新自本次加电开机以来的 **最高海拔**（`XX m`）。

## 五、 底层驱动调优与核心踩坑排障指南（关键经验库）

在此前联调过程中，发现了若干深层次的底层硬件兼容与内存分配问题，后续开发人员在增删代码时**必须严格遵守以下准则**：

### 5.1 规避 QSPI 屏幕“纯白屏”问题（片内 DMA SRAM 限制）
- **现象**：烧录后屏幕背光亮起但始终全白，无任何图形输出。
- **根因**：
  - ESP32-S3 的 General SPI Master DMA 控制器默认无法直接向外部 PSRAM 发起连续 DMA 搬运；
  - 若在 BSP 中将显存配置为 `.use_psram = true`，底层驱动每次刷新条带时必须从**片内内部 SRAM** 中动态分配一块等大的“弹跳缓冲区（Bounce Buffer）”；
  - 当条带高度过大（如 `buffer_height = 50`）时，单次需申请 $466 \times 50 \times 2 = 46.6\text{ KB}$ 连续片内内存；在 Wi-Fi 协议栈初始化后，片内内存碎片化导致 `setup_dma_priv_buffer` 报错 `ESP_ERR_NO_MEM`，显存未写入屏幕导致白屏。
- **规范要求**：
  - 必须保持 `.use_psram = false`，让 LVGL 绘制缓冲常驻在片内内部 DMA SRAM；
  - 保持 `.buffer_height = 20`（与官方出厂固件完全对齐），显存降至 $18.6\text{ KB}$，彻底根除白屏风险。

### 5.2 规避 LVGL v9 圆角裁剪（`clip_corner`）耗尽内存导致控件消失
- **现象**：三栏页面中只有中栏折线图显示，顶部海拔高度与底部极值消失不显示。
- **根因**：
  - 在大尺寸容器（如 $392\times 392$ 安全区）上开启 `clip_corner = true` 时，LVGL v9 渲染管线会在绘制上下边缘圆角时，为每个刷新条带动态申请 $392 \times 20 \times 4 = 31,360\text{ 字节}$ 的 `ARGB8888` 临时图层遮罩；
  - 该申请直接耗尽 LVGL 默认的 64KB 内存池，导致上下两个区域因内存分配失败而被静默跳过绘制。
- **规范要求**：
  - 物理屏幕本身为圆形 AMOLED，安全区容器**切勿**开启 `lv_obj_set_style_clip_corner` 或设置大圆角图层裁剪；直接采用坐标限制即可。

### 5.3 Quectel LC76G 模组 I2C 通信稳定性与时序法则
- **四步握手时序间隔**：
  - ESP32-S3 通过 I2C 轮询 LC76G 内部 NMEA 缓冲区时，从发出查询长度命令到读取数据，**各步骤之间必须严格保持 `>= 100ms` 的硬件任务延时**；
  - **严禁**使用 `< 20ms` 极短延时高频连读，否则会造成 LC76G 内部 I2C 从机 DMA 状态机在运行数十秒后死锁停振。
- **看门狗复位逻辑**：
  - **严禁**加入短周期（如 4 秒）无数据即硬件拉低 `EXIO7` 复位的逻辑，因为 GNSS 冷启动期间芯片需要持续追踪卫星信号，误触发硬件复位会导致已下载的星历帧被完全抹除，陷入无限冷启动死循环。
- **NMEA 跨帧解析**：
  - `$GNGGA` 和 `$GPGSV`/`$GBGSV` 异步到达，必须在内存中保持持久化的 `epoch` 结构体，禁止在收到 GGA 时将 GSV 统计的信噪比及可见星数直接归零。

### 5.4 USB 串口非阻塞日志输出
- 开发板采用内置原生 USB-Serial-JTAG 接口；
- 当设备未连接电脑上位机或连接但未开启串口监控软件时，底层 USB TX FIFO 填满后标准 `vprintf` 会使当前 FreeRTOS 任务彻底挂起；
- 系统已部署 [`nonblocking_usb_vprintf`](file:///Users/aubreyhan/Tools/git_repo/PersonalDev/EPS32/main/main.c#L25-L31) 机制，必须确保在任何场景下日志输出均不阻塞传感器 I2C 采集与 UI 渲染循环。

## 六、 常用开发与维护命令清单

```bash
# 1. 编译工程
idf.py build

# 2. 单独烧录应用程序 (速度极快)
idf.py app-flash

# 3. 擦除整片 Flash (仅在分区表重构或 NVS 损坏时使用)
idf.py erase-flash

# 4. 烧录完整固件并打开串口监视器
idf.py -p /dev/cu.usbmodem101 flash monitor

# 5. 查看系统动态堆内存与任务运行状态
idf.py monitor (按 Ctrl+] 退出)
```
